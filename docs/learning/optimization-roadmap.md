# 后续优化方法

先使用[实验模板](../templates/experiment.md)定义可复现问题、预期改善、设备环境、允许差异及回退步骤，再确定修改范围。

基础UI与球杆，以及动画/显示/场景、设置/AI/对局状态、输入/相机/回放三个装配批次均已完成行为刻画、拆分及验收。共享设置、编号、AI池、开球轮换和临时缓存有明确拥有者；模块和维护契约见[游戏装配](../architecture/game-composition.md)及[组合根维护说明](../architecture/composition-root-assessment.md)。后续按具体功能增加规则/Replay场景、构建诊断或硬件性能证据；CushionBody如需领域提取，另开算法刻画范围。

软件WebGL测试验证行为和布局，不能替代真实GPU计时。静态阴影已有[测量方法](../validation/interior-performance.md)；上下文恢复已加入独立[修复与验证](../validation/context-restoration.md)。材质闪烁及主观拖影仍需各自建立证据。改变物理参数、求解顺序、相机、纹理、灯光或阴影须明确允许差异并追加专项。

四套室内的相机时间归一化、固定 DPR 上限、瞄准/挥杆准备时长及首次说明时机已按用户要求实施，详见[操作流畅性](../validation/gameplay-motion.md)。继续优化材质或几何时，先复用四场景硬件测量建立证据，不因帧率问题直接减少八盏灯或关闭阴影。镜面闪烁、真实高刷新率显示和跨 GPU 的主观画面仍需单独验收。

当前服务使用no-store并通过刷新或重新构建更新。热更新、部署缓存策略、渲染引擎升级和大规模现代化应分别验证；此页是维护建议，后续执行范围由用户任务确定。
