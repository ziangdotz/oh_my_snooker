# 游戏内界面

Single Play与Practice沿用当前首页的深绿、暖金、真实Saira字体与细边框体系，布局和操作组织以独立冻结PCOL为参照。启动页、室内选择和About继续采用当前布局；游戏内不沿用它们的右侧抽屉结构。颜色维护在interior-tokens.css，游戏布局和响应式规则限定在game-ui.css的`.game-ui-`作用域。

| 内容       | 展示与操作                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 比分       | 原版46px横条，双人左右分布，Practice单侧；目标球、BRK和独立暖金分数格，长名字保留完整title和可访问名称，阶段只供辅助技术读取 |
| 工具栏     | 原生44px按钮，保留原Pause和Replay动作，图标和辅助名称一致                                                                    |
| 快捷提示   | 按原站立/瞄准状态显示，窄窗口折叠次要提示，完整操作保留在Controls Guide                                                      |
| 回放       | 原录制与控制器；原生播放/暂停/关闭按钮，进度条支持左右键、Home/End，控件聚焦后Space、C、S和Esc仍支持播放、相机、慢放与退出   |

通知按正文阅读量停留4至12秒，错误至少6秒；悬停、焦点进入及模态遮挡期间暂停计时。普通信息使用status/polite，错误使用alert/assertive。提示共用原版底部居中位置，临时通知显示时隐藏白球放置指引，通知结束后恢复，避免同时显示两个信息面板。快捷提示取消外层卡片，回放恢复底部通栏，双人模式工具栏按原版下移以避让比分。

重开或退出会清除上一局通知；手中球阶段根据当前控制器状态补充持续指引，离开放球阶段后清理。回放慢放状态在松键、焦点离开及退出时恢复，不影响原物理时钟。

## 生命周期与边界

私有默认工厂由[compose-game.js](../../src/application/compose-game.js)注入。原ActionDialog、DialogManager、MatchController、回放、计分与结果类继续用于字节和算法对照。game-ui-controller只读取原状态，不增加游戏状态机；结果页只转换显示文字及罚分展示，得分、赢家计算和裁判规则保持原实现。

面板通过原PropertyTween及应用时钟更新，退出动画完成后发出CLOSE并移出模态栈。嵌套关闭返回上一级按钮，最后一层关闭回到游戏画布。难度选择开始游戏后，旧首页关闭回调仅在首页仍活动时恢复菜单。没有替换全局RAF、时钟、键盘或WebGL接口，没有增加背景模糊或常驻动画。

游戏面板使用0.18秒的居中淡入；退出复用Tween并加速。减少动画模式缩至0.016秒；没有提示入场动画。480/720px CSS视口属于桌面窄窗口及放大等效检查，未增加移动设备完整游戏支持。

Controls Guide沿用560px居中面板及428px正文上限，标题与CLOSE固定，正文独立滚动。GENERAL的键盘示意与鼠标说明并列，窄窗口垂直排列；STANDING与AIMING使用语义化说明列表，将动作、操作和适用条件分为固定列，键帽统一30px，拖动/滚轮同时提供文字。480px以下条件移至操作下方，不影响按键列对齐。该布局由controls-guide.css维护，也用于BASIC CONTROLS的通用示意图；按键、Mac修饰键替换、暂停返回和游戏输入逻辑保持原流程。

## 验证

### PCOL布局回归

2026-10-09用户确认收敛界面：保留启动页、室内选择及About，游戏内大致1:1沿用PCOL位置、菜单顺序与操作路径，仅统一当前前端视觉。原版暂停重复的RESUME归并到首行；移除额外关闭按钮、可见阶段行、TARGET文字及结果卡片，不复制冻结代码或恢复无用资源。

`node tests/e2e/pcol-ui-layout.test.mjs`只读加载冻结PCOL，并使用HTTP响应插桩比较Chrome/Edge下原版与源码、开发及生产版本的比分外边界、工具栏高度、暂停中心及宽度、菜单顺序、难度和帮助宽度及正文高度；另查320px窄窗口比分边界。记录见[pcol-ui-layout.json](../../reports/validation/pcol-ui-layout.json)，行为及界面验证见[game-ui-browser.json](../../reports/validation/game-ui-browser.json)。已有game-ui专项继续覆盖四套场景、两种模式、嵌套焦点、默认取消、通知优先级及结果语义。当前布局以本页与实际源码为准。

### 无用旧界面清理

src不保存已被替代的原版UI作为备份。旧About弹窗、intro启动错误页、全屏旋转加载器、内容面板未调用的loading分支，以及18个失去用途的图片已删除；原版移动端启动画面不再登记。About直接注册当前抽屉，内部等待使用[game-loading.js](../../src/presentation/ui/game-loading.js)，与场馆加载共用卡片视觉，并在场馆加载或恢复显示时退让。启动失败、设备不支持和资源失败均使用当前恢复卡片。

game-base仅维护文档/画布、键帽、当前图标和目标球等有效基础；首页、游戏内及回放布局各自在当前组件样式中维护。仍被当前实现调用的类与图标继续保留，物理诊断面板的惰性注入接口仍可使用。冻结对照只存放在baselines，未复制进src。

`node tests/e2e/retired-ui-cleanup.test.mjs`检查Chrome/Edge的源码、开发及生产版本：旧DOM及18个旧资源不再交付、内部加载显隐及减少动画、场馆恢复优先、当前About注册、源码引导失败回退与重复ID。记录见[retired-ui-cleanup.json](../../reports/validation/retired-ui-cleanup.json)。算法结构验证仅放行已登记的纯显示方法/字段删除，仍比较这些类其余方法及全部物理/规则实现。

新专项`node tests/e2e/game-ui.test.mjs`覆盖Chrome/Edge、源码/开发/生产、四套设计及两种模式，共48条原生选择、暂停及返回首页流程。003 Practice另验嵌套面板、焦点循环与恢复、输入隔离、默认取消、通知优先级/去重/停留、窄窗口、结果展示和减少动画。结果卡片使用明确标记的展示数据，不能据此宣称完成整局比赛。

真实物理、规则、击球、回放插值及重开由game.test.mjs和continuous-play验证。原版与维护版的确认按钮由[game-ui-actions.mjs](../../tests/helpers/game-ui-actions.mjs)适配，游戏状态断言保持不变。原版UI及冗余基础样式已获准清理，当前UI通过布局和交互专项验收；物理、规则和场景对照保持不变，字体分别验证真实600及700字重。
