# 功能开发前的工程规范化

2026-10-11 至 2026-10-12 检查当前运行源码、构建与服务、配置、测试、文档、验证记录、资产和 Git 提交约定。范围是规范现有工程，双人模式和房间服务仍按[实施方案](../development/rooms-and-two-player-plan.md)后续开发。

## 审查结果与整理

115 个 runtime-catalog 模块全部从入口可达。当前 327 个 src 文件经过构建输入分类、工厂/ESM 导入检查和资源引用校验，没有未登记运行源码或孤立资产。旧基础 UI、输入和相机类仍被当前扩展继承，属于实际依赖；冻结程序是独立验证输入。

本轮实际运行修改限定为三个本地会话文件：launch-game 使用 userId / displayName，移除无用头像占位；LocalGameModel 改用具名本地会话转换；BaseGameModel 删除没有调用者的远程查询占位。既有启动数据、恢复时机与游戏设置保持。结构对照对这两类接口整理进行明确记录，其他运算继续比较，见[算法对照边界](algorithm-validation.md)。

构建工程补齐两项约束：ESM 相对导入执行与 loadModule 一致的依赖方向检查；球台配置中的碰撞 JSON 进入资产引用闭包，缺失时在构建前失败。物理文件、规则文件、模型、碰撞法线图、相机优化和冻结内容不修改。

增加 `check-maintenance` 作为整体检查步骤，检查模块可达性、资产引用、文档本地路径/锚点及 package 命令入口。常用专项已有命令入口，当前统一使用 npm；README、架构、开发流程、交接和产物说明明确已实现功能与双人开发提案的区别。

Git 忽略生成目录、缓存、截图及大体积逐帧原始测量，保留维护输入和统计摘要。室内性能摘要由已有报告派生，保留原始报告哈希与统计条件，不伪称新的硬件测量。移除七个无维护调用的临时实验脚本，正式测试、验证输入和已有有效证据继续保留。

## 验证

规范化后的整体浏览器检查完成 121 项单元/集成测试和 Chrome / Edge 回归。算法对照仍为 137 项，两个会话接口的允许改名/删除单独列出。新增架构测试阻断 ESM 越层引用和缺失碰撞 JSON；本地会话测试检查真实身份恢复与默认数据。

Git 集成测试在独立临时仓库中实际暂存、删除工作副本并重新检出 169 个冻结、资产与第三方文件，逐文件哈希保持，即使启用 core.autocrlf。自主 JS 与 Windows 启动脚本分别检出 LF / CRLF；忽略规则不会排除源码、基准或架构映射。测试没有初始化项目真实仓库。

规范化验收时，六项工程依赖的安装版本与 package.json 中固定版本一致，没有升级引擎或依赖。当前工程使用 npm 和 package-lock.json 管理工程依赖，安装与验证方式见[开发流程](../development/workflow.md)；浏览器仍使用本机版本。

以下五类追加专项均已通过，实际退出状态记录在[检查序列](../../reports/validation/project-normalization-checks.json)：

## 有意保留的维护边界

工厂 ABI、旧引擎适配、基础类继承及组合根中的 CushionBody 均有当前调用或初始化契约，不是无调用历史备份。CushionBody 的领域提取需独立数学刻画，不在本次本地会话与工程工具整理中改动。

保留物理源码 `collision-island.js` 中已有的 dispose 诊断文字由维护审计明确列出，其他自有运行实现不再有 TODO / FIXME 占位。该诊断属于保留内核的既有行为，不据此声称已验证其任意释放路径。后续内核改动需要对应生命周期和物理证据。

Git 首次建立与提交由使用者明确执行，步骤及署名边界见[仓库维护](../development/repository-workflow.md)。当前工程规范化没有创建远程仓库或执行推送。
