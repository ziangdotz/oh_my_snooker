# AI 与连续运行验收

## 范围与复现

运行 `node tests/e2e/continuous-play.test.mjs`，或 `npm run test:e2e:continuous`。开发和生产输出必须先通过完整校验；需要重新构建时运行 `node scripts/check-project.mjs --browser`。专项测试默认检测本机 Chrome 与 Edge，可用 `PCOL_BROWSER_PATH` 指定其他 Chromium 浏览器。

每个浏览器分别测试冻结基准与开发版，每条路线只有一个页面和一次导航。默认先完成 Practice 的 3 轮 × 6 杆；每杆执行真实放球（需要时）、W 瞄准、滚轮力度、Space 击球、回放暂停/播放/退出，每轮结束后通过 PAUSED → RESTART → YES 重开。之后在同一页面依次进入 AI-1、AI-2、AI-3，各执行两次人类及 AI 自主击球、球权回到人类、回放；两次之间重开，第二次结束后返回菜单。最后重新进入 Practice 检查初始状态恢复，再退出到菜单。

`--cycles 1..20` 与 `--shots 1..20` 可调整连续 Practice 负载；AI 每个难度仍执行两次测试。短负载适合诊断，不等同于默认负载验收。AI 如果合法进球继续持杆，测试等待其自然结束，不通过构造犯规切换球权。若人类开局得分继续持杆，最多执行六杆真实输入，仍未触发 AI 时明确失败。

等待人类球权以真实nRounds推进作为进度：每次必须在180秒内进入人类就绪状态或新增一个已判定回合，连续AI持杆最多观察64个已判定回合。状态切换、时间经过或动画本身不重置期限。这样正常长连击不会被总计180秒误判为停滞，真正无回合进度仍超时；不增加原无进度期限，不修改游戏时钟或随机数。等待条件与边界有[单元验证](../../tests/unit/human-turn-readiness.test.mjs)。

## 断言与证据

- 每次人类输入只报一杆，原始模型进入模拟，回合按顺序推进，后续击球产生新的录制标识。
- 三个难度确实选中相应 AI，并产生自主击球、真实模拟与判定；结束后回到人类球权。每个已判定回合的累计报杆次数等于回合计数。
- 球的坐标、速度和角速度保持有限数值；22 个球网格的可见状态、坐标与物理状态相符。比分、连击和目标显示与模型相符。
- 回放暂停跨八次引擎更新不移动，播放继续推进。退出回放保持规则上下文、玩家计数、比分、物理状态和录制标识，并恢复真实球显示。
- Practice 重开恢复初始规则、比分、罚分、连击、计数和全部球的布局/运动状态。不同模式切换后重新进入 Practice 也恢复其开局状态。
- 双人模式按原内核轮换开球方。测试在同步复位通知中记录原始规则、全部玩家计数与物理布局，断言恢复开局且开球方轮换，然后允许 AI 原样继续运行。不会在 AI 已完成开球后误要求回合数仍为零。
- 同一模式重开及继续运行时，场景网格、材质、纹理、引擎纹理缓存、帧观察器和渲染循环数量保持一致；基准与开发版的对应资源数量相同。WebGL 上下文不丢失，游戏只有一个渲染循环。
- 阻断非本地网络，检查页面异常、请求失败、缺失资源、崩溃和兼容诊断。测试前后再次验证冻结基准及两个交付目录，清单哈希必须不变。

插桩仅给测试页面的入口加载器增加检查句柄，并订阅原模型通知以保存中间 AI 回合。磁盘入口、物理、裁判、AI、时钟、随机数、输入和 WebGL 实现均不替换。用状态变化等待操作，不固定睡眠、不加速引擎。

完整数据写入 `artifacts/testing/continuous-play/report.json` 和各浏览器的 `*-baseline.json`、`*-runtime.json`。每个资源检查点增量保存记录，失败时尽力保留最后现场、页面截图和原异常。结果按本次实际负载、版本及浏览器解释。

## 资源观察的解释

通过 Chromium CDP 被动采集 JS 堆使用/容量、保留 DOM 节点、文档与 JS 事件监听器数量，同时记录当前文档可见节点与场景资源。没有强制垃圾回收；堆和保留节点可能在 GC 前上升，不能把首末差值直接等同于内存泄漏。场景资源断言针对同一模式的对应状态，不把不同界面的 DOM 数量硬判为相同。跨 AI 模式重新进入 Practice 时也核对场景资源恢复。

专项执行有限负载连续运行与状态恢复验收，不声称覆盖完整比赛、所有犯规、数小时无人值守或所有随机 AI 分支。浏览器仍使用 headless 软件 WebGL；真实GPU测量另见[阴影性能方法](interior-performance.md)。

堆采样包含测试自有的通知记录缓冲区，不代表未插桩页面的绝对内存占用。日志和样本保存的是本轮可观察证据，不将随机对局的得分或轨迹要求为逐帧一致。

专项全程持有两份构建锁，并保存前后清单快照与差异诊断；行为用例通过真实输入和原生时钟执行。
