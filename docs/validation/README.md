## 工程与算法

整体检查覆盖目录、命名、lint、开发/生产构建、输入输出完整性、维护审计、格式及单元/集成测试。维护审计核对文档、命令、模块、资产及 npm 锁文件一致性。构建校验源码、模块依赖、资源引用闭包和逐文件SHA-256；冻结文件集合、大小和哈希独立校验。隔离故障测试验证无效输入、过期输出、并发构建、事务发布与失败恢复。

算法结构对照见[方法](algorithm-validation.md)。reports/validation/architecture-migration-map.json为机器读取的源码与基准映射，验证137项解析后的算法结构；改写的碰撞加载器另有专项功能验证，它不能证明任意装配搬移或运行行为等价。

[球杆装配验证](../architecture/cue-composition.md)用拆分前后的同组断言检查请求去重、重试、错误、材质参数、共享编号及场景隔离，并用真实Babylon类型和模型文件补充引擎集成。文件缓存不依赖场景，材质和网格仍由各管理器拥有。

[游戏装配](../architecture/game-composition.md)补充显示/场景、设置/对局、输入/回放三组行为专项，共18项先后使用同组断言；另复核18组搬移声明的表达式、运算符、对象键与语句顺序。每批浏览器及后两批默认连续玩法的范围、源码哈希与结果见[当前装配记录](../../reports/validation/game-composition.json)。旧报告只证明其记录的输入，不自动视为当前源码复测。

## 浏览器

tests/e2e/game.test.mjs阻断非本地请求，在Chrome/Edge比较渲染和相机参数、五组物理初态、计分犯规、真实放球与击球、Replay、续杆及重开。每组物理场景运行480步，采样25帧与22个球；Replay读取原录制数据对照位置和可见性，记录不含旋转。

规则专项使用原模型入口构造接触/入袋结果，覆盖红彩切换、罚分、白球复位、球权、连击及清彩状态；受控规则结果不能称为真实物理击球。恢复专项另通过真实两杆、回放退出与重开核对模型和球状态。

源码独立复制、原始场景五视角、室内选择/字体/恢复、游戏界面/布局/矢量图和阴影均有独立专项。[WebGL完整恢复](context-restoration.md)覆盖四个室内方案的连续真实丢失、精确画面、恢复后击球/Replay/重开和闲置首页自动刷新。室内统一入口包含六套测试；新增[同页切换](../../tests/e2e/interior-switching.test.mjs)核对同一引擎/场景/球、有界缓存和独占灯光，逐像素比较直接加载，测量实际切换，并验证全部室内缓存后的WebGL恢复。其他专项按修改范围运行。连续AI测试见[方法](continuous-play.md)，真实GPU阴影测量见[说明](interior-performance.md)。

测试以真实状态变化等待，不通过固定睡眠、替换全局时钟/RAF或放宽行为断言处理失败。浏览器诊断保存在artifacts/testing，JSON结果在reports或对应测试主题；失败先检查phase、diagnostics、异常及截图。

## 限制

[游戏操作流畅性](gameplay-motion.md)单独记录用户授权的相机时间、操作节奏与 DPR 上限变化，并用更新频率刻画和四场景真实硬件输入专项验证。137 项原算法结构对照仍然检查保留实现；扩展的当前行为由新专项证明，不将其解释为与冻结版本完全相同。

有限测试不覆盖完整一局、全部犯规、全部随机AI分支或数小时稳定性。软件WebGL通过不代表真实GPU性能或跨设备像素一致。Firefox、Safari和完整移动设备游戏尚未验收。结果应依据对应日期、源码和场景解释，不把旧结果自动视作新修改的复测。
